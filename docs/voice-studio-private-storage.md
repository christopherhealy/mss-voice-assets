# Studio private audio storage and playback — disabled

`createVoiceStudioPrivateStorage` uses a dedicated R2 client with Voice Studio-specific credentials. Legacy uploadToR2/checkR2Access behavior is unchanged. The private QA bucket `voice-studio-private-qa` has been created with public access disabled, and dedicated bucket-scoped credentials have been created. The bucket name and credentials have been saved in the Render QA environment, but not deployed. Encryption keys, service authentication, generation approvals and live startup wiring remain unconfigured. The Studio endpoint still uses enabled=false and cannot be activated with an environment flag.

The factory requires a separately reviewed private bucket distinct from the legacy public bucket, an explicitly supplied 32-byte encryption key/key ID, the single approved studio:<generation-key> asset identity, and the exact QA service environment. `privateBucketReviewed` is an operator-owned precondition, not evidence that a bucket policy was inspected by the code. Before live use, verify no public domain/r2.dev access or public bucket policy, and review existing client's access to the dedicated bucket. A path prefix does not make a public bucket private.

Object key: private/voice-studio/julie/it/l2-scripted-host/<generation-key>.enc. No public or signed object URL is constructed or returned. Each object is an AES-256-GCM encrypted, versioned envelope, stored as application/octet-stream with no-store. AAD binds application, asset identity and encryption-key ID. Use protected key custody (prefer a separate key from the journal), retain keys for recovery, and never log or commit keys. The object contains audio only; HeyGen recovery URLs remain in the separately encrypted journal.

Preflight is a HeadBucket call, which establishes reachability only, not guaranteed PutObject permission. Upload failure preserves the route's existing encrypted recoverable journal state. Successful object write precedes markStored; a dedicated journal update registers the asset. Final completion changes state, encrypted metadata and opaque storage references together using the existing CAS UPDATE. Object storage and PostgreSQL cannot be committed atomically: a failed final DB acknowledgement may leave an unreferenced object; explicit recovery safely re-stores the same validated audio without new generation. No uncertain claim is released automatically.

GET /api/voice/studio-audio?asset_id=studio:<key> reuses the existing distinct Voice Studio service authentication: X-Service-ID voice-studio and its Bearer service credential. It requires current server-owned approved Julie/Italian profile and the journal's exact application/context identity. Only ready records with matching opaque storage references and a recorded byte hash can be served. GET does not require or invoke generation, translation, provider credentials or generation approvals. It loads the private object, authenticates/decrypts it and verifies the journal SHA-256 before streaming the bounded MP3 to the HTTP response with no-store and nosniff. No recovery URL, object location, provider JSON or credential is returned by playback.

This is server-to-server authorization, not learner authentication. Actor’s Studio's server must authenticate its users, authorize script/turn access and proxy playback. Never put the VoiceAssets service credential or encryption keys in browser JavaScript. Actor’s Studio integration is deliberately not changed. The generation/recovery response retains its existing server-only accounting fields (including provider request ID); those should not be blindly forwarded to browsers.

For this short-line prototype, authenticate the complete encrypted object before streaming plaintext. Maximum MP3 size is 20 MiB; full ciphertext is bounded to 40 MiB. There is no byte-range/seek support. MP3 validation checks MIME-independent magic and size, not full codec decoding. Playback never calls HeyGen; repeated listens read cached bytes only. Existing browser speech and Live behavior are unaffected.

Offline tests use synthetic ID3-prefixed bytes, mocked S3 commands and the existing mock PostgreSQL journal fixture. They exercise authenticated writable-stream responses, encryption/tamper detection, wrong-application/profile rejection, playback without generation dependencies, upload/download failure, new-instance recovery and completed-state integrity. This does not verify real R2 policies, permissions, provider delivery, browser decoding or live deployment readiness.
